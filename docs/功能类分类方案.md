## 0. 这份文档怎么用

- **查某条规则属于哪类**：用 `docs/功能类分类映射.csv` 按分组名筛选，或在第 7 节附录按应用检索。
- **看某类都有哪些规则**：直接翻到第 7 节对应子类小节，每组标注应用与规则数。
- **新增规则怎么归类**：先看第 6 节判定顺序，命中即止；确实归不进去就放 H1，不硬塞。
- **本文件不改变订阅行为**：`gkd.json5` 未做任何修改，分类仅作文档与后续决策依据。

## 1. 结论先行

| 项 | 结论 |
| --- | --- |
| 分类维度 | 按**用户意图**（这条规则替用户完成了什么），不按应用、不按控件类型 |
| 层级 | 两级：**功能族（8）→ 子类（34）** |
| 可落地方式 | 子类只能写进 `group.name` 前缀；`order` 是匹配优先级，不能用于界面排序 |
| 最大子类 | 签到与打卡（39 组）、弹窗与提示关闭（34 组）、自动点击与导航（27 组） |
| 待人工确认 | 10 组落入“其他自动化”，其余 466 组均有明确归属 |

## 2. 分类原则

1. **按意图而非按应用**：同一条“自动查看原图”出现在微信、QQ、微博，归入同一子类。
2. **互斥优先**：一条规则只落一个子类；多重语义时按“用户最想达成的结果”判定，而非按实现手段。
3. **动作优先于场景**：“关闭登录弹窗”是关弹窗（G1），不是登录（C1）；“关闭免密支付弹窗”是关弹窗，但“关闭小额免密支付”本身是支付设置（C3）。
4. **尊重 GKD 机制**：分类归属由 `name` 前缀匹配 `categories[].name` 决定（见 GKD `RawCategory`），因此子类若要在客户端可见，必须体现在名称上。
5. **可增长**：新增规则先判断族，再判断子类；无法归类时进 H1，不硬塞。

## 5. 落地方式对比

| 方案 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| A. 仅文档 | 保留本文件与映射 CSV，`gkd.json5` 不动 | 零风险，可作为评审基线 | 客户端看不到分类 |
| B. 命名前缀 | `功能类-查看原图-微博` 式重命名 476 个分组 | 客户端可见、按名称自然聚簇、`key` 不变则用户开关状态不丢 | 一次性改动量大，所有用户可见名称变化 |
| C. 独立分类 | 在 `categories` 新增「查看原图」「签到」等顶级分类 | 可在分类列表整体启停 | 顶级分类膨胀，偏离 GKD 通行 11 分类；子类过多时不可行 |

**建议**：先做 A 评审分类本身；确认后执行 B，且只对**用户高频**的前 12 个子类加前缀（签到、查看原图、展开评论、登录授权、安装更新、关闭弹窗、支付订单、看广告、权限授权、红包、倍速、流量），其余保持原名。这样收益集中、改动可控。

### 命名前缀规则

```text
功能类-<建议前缀>-<原语义>
功能类-查看原图-微信        ← 原：功能类-自动查看原图
功能类-展开评论-抖音-评论区-自动展开评论  ← 允许保留原二级结构
```

- 前缀取 2–4 字，保证列表内可扫读；
- 不改 `key`、不改 `rules`，仅改 `name`，用户启用状态不受影响；
- 重名冲突时在末尾追加应用名或原后缀，不改前缀。

## 6. 边界判定规则

判定顺序（自上而下，命中即止）：

1. 播放控制类关键词（倍速/静音/弹幕/上滑）→ B 族；
2. 明确的资产动作（签到/红包/领取/看广告）→ D 族；
3. 安装与风险验证 → E1/E2，其中“风险、安全检测、验证、来源不可信”优先于“安装”；
4. 权限、屏幕共享、USB、定位 → E3；跳转外部应用 → E7；下载与文件 → E8；
5. 登录、扫码确认、授权登录 → C1；纯“打开扫一扫”入口 → G4；
6. 支付、免密、先用后付、收货 → C3；若名称主体是“关闭某弹窗” → G1；
7. 展开评论/回复 → A1；其余展开、显示更多、敏感内容 → A2；
8. 兜底：关闭/提示/邀请 → G1；返回/完成/确定 → G3；拒绝/屏蔽/禁止 → G5；其余 → H1。

典型易错例：

| 分组名 | 归属 | 理由 |
| --- | --- | --- |
| 功能类-关闭登录备份翻译记录弹窗 | G1 | 主体是关弹窗，不是翻译 |
| 功能类-关闭小额免密支付 | C3 | 改的是支付设置，不是关弹窗 |
| 功能类-展开全部订单信息 | A2 | 展开内容，不涉及交易动作 |
| 功能类-自动点击右上角扫一扫 | G4 | 扫码只是入口，没有登录确认 |
| 功能类-上传后自动修改处方 | G4 | 业务流程推进，与支付无关 |
